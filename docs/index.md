# ZeroTier Provider

This terraform provider allows you to stitch the following objects from the [ZeroTier Central API](https://my.zerotier.com/help/api):

- Networks
- Members
- Identities

## Central V1 and Central V2

The provider manages both ZeroTier Central APIs, and one configuration can use both at once:

- **Central V1** (`my.zerotier.com`): the `zerotier_network`, `zerotier_member` and `zerotier_token`
  resources. Set `zerotier_central_token` (or `ZEROTIER_CENTRAL_TOKEN`).
- **Central V2** (`central.zerotier.com`): the `zerotier_v2_*` resources for network groups, networks,
  members, service accounts and API keys. Set `zerotier_central_v2_api_key`
  (or `ZEROTIER_CENTRAL_V2_API_KEY`) to a service account API key.

Each credential is only needed for the resources that use it. `zerotier_identity` needs neither.

```terraform
provider "zerotier" {
  # Central V1, from ZEROTIER_CENTRAL_TOKEN when unset
  zerotier_central_token = var.central_v1_token

  # Central V2, from ZEROTIER_CENTRAL_V2_API_KEY when unset
  zerotier_central_v2_api_key = var.central_v2_api_key
}
```

## Example Usage

```terraform
terraform {
  required_providers {
    docker = {
      source = "kreuzwerker/docker"
    }
    # FIXME update for final zerotier source location
  }
}

provider "docker" {}

resource "docker_network" "private_network" {
  name = "my_network"
}

resource "docker_image" "zerotier" {
  name         = "erikh/zerotier"
  keep_locally = true
}

resource "docker_container" "alice" {
  name    = "zerotier_alice"
  image   = docker_image.zerotier.image_id
  command = [zerotier_network.docker_network.id]

  devices { host_path = "/dev/net/tun" }

  capabilities {
    add = ["CAP_NET_ADMIN", "CAP_SYS_ADMIN"]
  }

  upload {
    file    = "/var/lib/zerotier-one/identity.public"
    content = zerotier_identity.alice.public_key
  }
  upload {
    file    = "/var/lib/zerotier-one/identity.secret"
    content = zerotier_identity.alice.private_key
  }
}

resource "docker_container" "bob" {
  name    = "zerotier_bob"
  image   = docker_image.zerotier.image_id
  command = [zerotier_network.docker_network.id]

  capabilities {
    add = ["CAP_NET_ADMIN", "CAP_SYS_ADMIN"]
  }

  devices { host_path = "/dev/net/tun" }

  upload {
    file    = "/var/lib/zerotier-one/identity.public"
    content = zerotier_identity.bob.public_key
  }
  upload {
    file    = "/var/lib/zerotier-one/identity.secret"
    content = zerotier_identity.bob.private_key
  }
}

provider "zerotier" {}

  name = "docker"

  assignment_pool {
    start = "10.0.1.2"
    end   = "10.0.1.253"
  }

  route {
    target = var.ipv4_cidr
    via    = "10.0.0.1"
  }

resource "zerotier_identity" "alice" {}

resource "zerotier_member" "alice" {
  name       = "docker-alice"
  member_id  = zerotier_identity.alice.id
  network_id = zerotier_network.docker_network.id
}

resource "zerotier_identity" "bob" {}

resource "zerotier_member" "bob" {
  name       = "docker-bob"
  member_id  = zerotier_identity.bob.id
  network_id = zerotier_network.docker_network.id
}
```

## Schema

### Optional

- `zerotier_central_token` (String) ZeroTier Central V1 API Token; you can generate a new one at https://my.zerotier.com/account. Required for the V1 resources (zerotier_network, zerotier_member, zerotier_token). Can also be set with ZEROTIER_CENTRAL_TOKEN.
- `zerotier_central_url` (String) ZeroTier Central V1 API endpoint. Unlikely you'll need to alter this unless you're testing ZeroTier central itself. Can also be set with ZEROTIER_CENTRAL_URL.
- `zerotier_central_v2_api_key` (String, Sensitive) ZeroTier Central V2 service account API key. Required for the zerotier_v2_* resources. Can also be set with ZEROTIER_CENTRAL_V2_API_KEY.
- `zerotier_central_v2_url` (String) ZeroTier Central V2 API endpoint. Defaults to https://central.zerotier.com. Can also be set with ZEROTIER_CENTRAL_V2_URL.
